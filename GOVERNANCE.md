# Governance

## Estructura del Proyecto

### Roles

#### Maintainers
- Responsables del mantenimiento general del proyecto
- Revisan y aprueban pull requests
- Mantienen la documentación
- Responden a issues y discussions

#### Contribuidores
- Cualquiera que contribuya al proyecto
- Pueden enviar pull requests
- Pueden reportar bugs y sugerir funcionalidades

### Decisiones

#### Proceso de Toma de Decisiones
1. **Pequeños cambios**: Los maintainers pueden aprobar directamente
2. **Cambios significativos**: Requieren discusión en issues o discussions
3. **Cambios mayores**: Requieren votación de la comunidad

#### Consenso
- Se busca consenso entre los maintainers
- En caso de desacuerdo, se vota
- La mayoría simple gana

### Comunicación

#### Canales
- **GitHub Issues**: Para bugs y funcionalidades
- **GitHub Discussions**: Para preguntas y discusiones
- **Email**: Para asuntos privados

#### Frecuencia
- Issues: Respuesta en 48 horas
- Pull Requests: Revisión en 72 horas
- Discussions: Respuesta en 1 semana

### Procesos

#### Pull Requests
1. Crear PR con descripción clara
2. Esperar revisión de maintainer
3. Address feedback
4. Merge cuando sea aprobado

#### Releases
1. Crear rama de release
2. Actualizar changelog
3. Crear tag
4. Publicar release

#### Hotfixes
1. Crear rama de hotfix
2. Aplicar fix
3. Crear PR
4. Merge y release inmediato

### Conflictos

#### Resolución
1. Discusión en el issue/PR
2. Mediación por maintainer
3. Votación si es necesario
4. Decisión final del maintainer líder

### Cambios en la Governance

Este documento puede ser modificado por los maintainers con aprobación de la mayoría.
